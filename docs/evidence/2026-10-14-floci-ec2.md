# Floci AWS — EC2 bootstrap and health

Date: 2026-10-14
Environment: Floci AWS 2.1.0
Validation: local-emulator

## Validated capabilities

- VPC, subnets, routing and NAT control plane
- EC2 simulated with a Docker container
- Instance provisioned using OpenTofu
- UserData bootstrap executed
- HTTP health endpoint operational
- Health verified locally and between containers
- OpenTofu reconciliation: No changes (exit 0)

## Troubleshooting evidence

Initial bootstrap failed because of APK lock
contention and package repository TLS errors.

Resolved by removing package installation from
UserData and using built-in BusyBox networking.

## Emulator limitation

The instance reported the default Security Group
rather than the explicitly configured group.

Reconciliation failed because the Floci EC2 API
does not support ModifyNetworkInterfaceAttribute.

The local stack now uses the emulator-assigned
default group. AWS-equivalent security group
enforcement was not demonstrated.

## Remaining limitations

- NAT packet forwarding not validated
- Cloud parity not claimed
- Automated readiness timeout not implemented
- Service restart recovery not validated
